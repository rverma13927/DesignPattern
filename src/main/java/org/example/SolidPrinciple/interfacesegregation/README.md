Interface Segregation Principle (ISP) – Explained Simply
The Interface Segregation Principle states:

A class should not be forced to implement interfaces it does not use.

In other words:

Interfaces should be small and specific.
Each interface should have only the methods that are relevant to a particular class.
No class should be burdened with unnecessary methods.
Why is ISP important?
Reduces the impact of changes (changing one method doesn't break unrelated classes).
Makes the code more modular and easier to understand.
Helps avoid creating "fat interfaces" with too many unrelated methods.

Benefits of ISP:
Avoids large, bloated interfaces.
Reduces unnecessary code in classes.
Improves maintainability because each class deals with only relevant functionalities.
Makes the system more flexible and modular.
