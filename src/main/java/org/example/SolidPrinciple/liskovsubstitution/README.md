Liskov Substitution Principle (LSP) – Explained Simply
The Liskov Substitution Principle states that:

Objects of a superclass should be replaceable with objects of its subclasses without affecting the behavior of the program.

In other words:

A child class should extend the behavior of the parent class without changing its original behavior.
If class B is a subclass of class A, you should be able to replace A with B without breaking the program.
Why is LSP important?
Ensures that inheritance is used correctly.
Prevents unexpected behavior in the program.
Promotes code reusability and maintainability.
